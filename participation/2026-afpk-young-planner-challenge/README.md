# 📝 제1회 AFPK 영 플래너 챌린지 2026 (AI 재무설계 콘테스트)

**주제** 불규칙한 소득구조를 가진 1인 미디어 콘텐츠 창작자를 위한 AI 기반 동적 재무설계
**과제** B안 · 가상 고객(먹방 유튜버) · **기간** 2026.10.08 ~ 11.16 (제출) · **결과 발표** 2026.12.07
**내 역할** 데이터 분석·보고서 (계산 기준 검증, 앱 구조 설계, 보고서 작성, 부록 검증 내역)

> 먹방 유튜버(가상 고객)를 위한 AI 기반 동적 재무설계 공모전. 상경계(재무 논리)와 개발(앱 구현) 사이에서 **계산 기준의 일관성을 검증**하고, **서술형 재무 아이디어를 앱에 넣을 수 있는 수치·규칙으로 바꾸는** 역할을 맡았습니다.

## 👥 팀 구성 (4인)

| 역할 | 인원 | 담당 |
|---|---|---|
| 재무설계 | 2명 (상경계) | 고객 설정, 재무목표·전략, 부록 작성 |
| 앱 개발 | 1명 | Streamlit 구현, Pyomo·HiGHS 최적화 |
| **데이터 분석·보고서** | **1명 (나)** | 계산 기준 검증, 앱 구조 설계, 보고서 작성, 부록 검증 내역 |

## ✍️ 내가 한 일

### 1. 계산 기준 검증 — 재무팀 초안을 앱이 처리할 수 있는 규칙으로
- 재무팀 초안을 개발 관점에서 검토해 **피드백 14개 항목** 작성 (문제 → 앱에서 왜 필요한지 → 제안 → 답변 칸)
- 주요 발견과 반영 결과

| 유형 | 발견 | 반영 |
|---|---|---|
| 수치 불일치 | 결혼자금 3,000만/2,000만, 주거비 65만/70만 | 통일 |
| 중복 집계 | 자산 항목이 서로 포함 관계인지 불명확 | 모두 별도 자산으로 확정 |
| 정의 모호 | 사업비가 두 번 차감될 수 있는 산식 | **잉여자금 = 매출 − 사업비 − 세금준비금 − 생활비**로 순서 고정 |
| 고정값 | 잉여자금을 20만/550만 원으로 고정 | 매월 실제 매출 기반 계산으로 변경 |
| 근거 부재 | 세금준비금 비율, 월 고정수입 목표 | 세금 약 8.4% → 10%, 필수생활비 145만 → 목표 150만 |
| 구현 불가 형태 | 줄글로 된 위험상황 | 수입원별 %·비용·기간으로 수치화 |

- 합의한 산식으로 소득 구간별 예시(매출 200·230·260·500·800만 원)를 다시 계산해 잉여·부족액이 일관되게 나오는지 확인

### 2. 앱 전체 구조 설계
- 앱 흐름 1~10단계 중 **2~9단계 구상·제안** (Streamlit 구현은 개발 담당)
- [3. Validation] 형식·누락·금액 검사, 데이터 정규화 제안
- [8. AI Advisor] 결과 설명·개인화·실행계획 작성 기능 기획 주도
- 원칙: **금융 계산은 Python/Pyomo, AI는 해석·설명만**

### 3. 보고서 작성 (본문 전체)
- 회의록 → 재무설계 → 앱 구상록 → 실제 앱까지 점검해 1차본 작성 → AI 활용 2차본 → 중복 통합해 **6단계 + 결론 11쪽** 최종본
- 스토리라인 5가지: 직업 → 재무 문제 도출 / 돈의 총액보다 역할 / 소득 구간별 차등 관리 / 목표 간 충돌과 한계 인정 / 전공이 다른 관점이 하나의 계산 규칙으로
- 세율·세액공제 법령 출처 보강, 결론·참고자료 작성, 블라인드 점검(작성자명 제거, 앱의 실명 테스트 기록 발견)

### 4. 앱 결과 독립 검증 → 보고서 반영 (제출 3일 전)
- 앱의 위험상황·전략 최적화·전략 평가를 직접 실행해 **손계산과 대조** → 배분예산 793만 원, 추가 세금준비금 37만 원, 평가 총점 일치
- 숫자만 봐서는 안 보이는 문제 발견
  - 위험상황 C: 증가율이 매출이 낮은 기준 월에 곱해져 의도(+500만)와 다른 결과(+241만)
  - 추천 전략(균형형)이 사실상 가중치 10% 항목(위험성향 적합도) 하나에 좌우됨 → 이 항목을 빼면 성장형이 근소하게 1위
  - 보고서와 앱의 자산 분류 불일치(투자자산 1,600만 원) → 통일
- 핵심 근거: 실제 지출 기준 잉여 145만 원 → 권고예산 적용 시 793만 원(약 5.5배), 결혼자금 연 필요액 250만 원 확보

### 5. 부록 '검증·수정 내역'
- AI가 계산한 세액(약 302만 원)을 과세표준과 세율로 다시 확인하고 **"추정치이지 확정 세액이 아님"**을 구분
- 세금준비금 10%를 "법정 세율"이 아닌 **"보수적인 현금관리 기준"**으로 명시

## 🙅 내가 하지 않은 것
- 앱 코딩·구현, 최적화 모델 수식 설계 (개발 담당)
- 고객 설정, 재무목표, 전략 내용, 부록의 도구·활용 내역 대부분 (재무팀)
- 정량 효과(오류 감소율 등)는 측정하지 않았으므로 주장하지 않음

## 💡 배운 것
- **"사람이 읽는 기준"과 "코드가 읽는 기준"은 다르다.** 월 300만 원이라는 숫자도 재무 관점에서는 저축 여력, 데이터 관점에서는 총매출과 가용소득의 구분, 개발 관점에서는 차감 순서의 문제였다.
- **계산 결과가 맞는 것과 결론이 타당한 것은 다르다.** 점수 계산은 정확했지만, 항목별로 나눠 보니 추천이 기준 하나에 기대고 있었다.
- AI는 초안을 빠르게 만들고 정리하는 데 강하지만, **원자료와 대조하고 채택 여부를 정하는 건 내 일**이었다.

**아쉬운 점** 해커톤과 일정이 겹쳐 중반 참여가 느슨해졌고, 앱 결과 검증을 마감 직전에야 했다. 다음에는 역할·일정을 처음에 명확히 정하고 결과물 중간 점검 일정을 따로 잡을 것.
